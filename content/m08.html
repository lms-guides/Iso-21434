Notifications, event groups and buffers

Once queues and semaphores are solid, these primitives let you delete most of them — and make ISR hand-off cheaper and clearer.

  • Task notification
  • Event group
  • Stream buffer
  • Message buffer

By the end of this module

  • Replace a semaphore with a task notification where it fits.
  • Wait on a combination of conditions with an event group.
  • Stream bytes and variable-length frames without a queue per byte.

Direct-to-task notifications

Each task has an array of notification slots (configTASK_NOTIFICATION_ARRAY_ENTRIES, default 1). Each slot has a pending flag and a 32-bit value. Sending a notification unblocks the task directly — no queue object, roughly 45% faster and much smaller than a semaphore, according to the FreeRTOS documentation.

/* Producer side, exactly like a binary semaphore */
vTaskNotifyGive(xConsumerTask);
vTaskNotifyGiveFromISR(xConsumerTask, &xWoken);

/* Consumer side: clear to zero on exit (binary) or decrement (counting) */
for (;;) {
    uint32_t ulCount = ulTaskNotifyTake(pdTRUE, portMAX_DELAY);
    while (ulCount--) {
        do_one_unit_of_work();
    }
}

For values and flags rather than counts:

/* eSetBits ORs the value into the notification; eIncrement adds one;
   eOverwrite replaces it. */
xTaskNotify(xTarget, EVT_RX_READY | EVT_DMA_DONE, eSetBits);

uint32_t ulValue = 0;
xTaskNotifyWait(0, 0xFFFFFFFF, &ulValue, pdMS_TO_TICKS(100));

/* A second, independent channel */
xTaskNotifyIndexed(xTarget, 1, 1, eSetBits);

Limits: exactly one waiter per slot, a 32-bit payload, and the sender cannot block waiting for the receiver. That is fine for the vast majority of driver-to-task signalling, and it is the right default for ISR hand-off.

Event groups

Bits can be set independently by tasks and ISRs, and a task can wait for any or all of a mask:

#define EVT_WIFI_UP     (1u << 0)
#define EVT_TIME_VALID  (1u << 1)
#define EVT_SD_READY    (1u << 2)

void vNetTask(void *pv)
{
    (void)pv;

    for (;;) {
        EventBits_t xBits = xEventGroupWaitBits(
            xEvents,
            EVT_WIFI_UP | EVT_TIME_VALID,   /* bits to wait for   */
            pdTRUE,                         /* clear on exit      */
            pdTRUE,                         /* wait for ALL       */
            pdMS_TO_TICKS(30000));

        if ((xBits & (EVT_WIFI_UP | EVT_TIME_VALID)) ==
            (EVT_WIFI_UP | EVT_TIME_VALID)) {
            start_tls_session();
        } else {
            report_timeout(xBits);          /* shows which bit is missing */
        }
    }
}

From an ISR, xEventGroupSetBitsFromISR() defers the update through the timer daemon task, so it requires configUSE_TIMERS and a timer command queue. The function can therefore fail with pdFAIL if the queue is full, unlike a task-level set.

The timeout return value is diagnostic gold: it tells you which condition never arrived. Use event groups for “system is ready” gates, fault flags and multi-condition startup sequencing. They are not counters — a bit set twice is still one bit.

Stream and message buffers

A queue stores fixed-size items. A stream buffer stores bytes, designed for single-writer/single-reader byte streams: UART RX/TX, DMA hand-off, logging.

StreamBufferHandle_t xRx = xStreamBufferCreate(256, 1);  /* size, trigger */

/* ISR */
size_t n = xStreamBufferSendFromISR(xRx, &ucByte, 1, &xWoken);

/* Task: block until at least the trigger level is available */
size_t got = xStreamBufferReceive(xRx, buf, sizeof buf, portMAX_DELAY);

A message buffer is the same object with a length prefix, so it can carry variable-length records — one JSON line, one protocol frame — instead of single bytes.

Both require exactly one reader and one writer. With several producers, put a queue or a mutex in front. Unlike a queue, they truncate rather than block a sender forever on the ISR path, so check the return value and count losses.

Choosing a primitive

NeedPrimitive
One producer, one consumer, fixed-size itemsQueue
Many producers, one consumer, fixed-size itemsQueue
ISR → task, “go do the thing”, one waiterTask notification
ISR → task, every event must be countedCounting semaphore or queue
Wait for A and B (and C)Event group
Byte stream from UART or DMAStream buffer
Variable-length framesMessage buffer
Protect a peripheral across tasksMutex, or a gatekeeper task
Protect a few instructions shared with an ISRCritical section

Key takeaway

Reach for a notification first for one-to-one signalling, a queue for data, and an event group for conditions. The cheapest primitive that expresses the invariant is also the easiest to review.
