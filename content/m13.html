Capstone: build a sensor data logger

Everything from Modules 1–12, in one product: sampling, processing, storage, a command line, health supervision and a watchdog.

  • Bring the system up in seven verifiable milestones.

Specification

  • Read temperature and humidity at 100 Hz over I2C.
  • Apply a moving-average filter; flag samples that cross configurable thresholds.
  • Write samples to SD card in 1-second batches, tolerating a 200 ms card stall without losing samples.
  • Provide a UART command line: status, rate <hz>, threshold <t>, dump.
  • Blink a status LED: 1 Hz healthy, 5 Hz fault.
  • Detect a stalled task within 2 s, log it, and reset if it does not recover.
  • Run on a Cortex-M4 with 128 KB RAM and a 1 kHz tick.

Check the numbers before writing code. sensor needs 1.2 ms every 10 ms (12%), process 0.4 ms (4%), storage 80 ms per second (8%), and the rest is under 2%. Total under 30%, leaving plenty for ISRs and the tick. The queue from sensor to process needs at least 100 Hz × 0.2 s = 20 slots if process can be delayed by storage; use 32.

The data path

/* app_main.c */
QueueHandle_t xSampleQueue;   /* sensor  -> process  */
QueueHandle_t xRecordQueue;   /* process -> storage  */
QueueHandle_t xCmdQueue;      /* cli     -> others   */
StreamBufferHandle_t xCliRx;  /* UART ISR -> cli     */

void app_start(void)
{
    xSampleQueue = xQueueCreate(32, sizeof(SensorSample_t));
    xRecordQueue = xQueueCreate(64, sizeof(Record_t));
    xCmdQueue    = xQueueCreate(8,  sizeof(Command_t));
    xCliRx       = xStreamBufferCreate(256, 1);

    configASSERT(xSampleQueue && xRecordQueue && xCmdQueue && xCliRx);

    xTaskCreate(vHealthTask,  "health",  256, NULL, 5, NULL);
    xTaskCreate(vSensorTask,  "sensor",  384, NULL, 4, NULL);
    xTaskCreate(vProcessTask, "process", 512, NULL, 3, NULL);
    xTaskCreate(vStorageTask, "storage", 768, NULL, 2, NULL);
    xTaskCreate(vCliTask,     "cli",     512, NULL, 2, NULL);
}
/* sensor_task.c */
static void vSensorTask(void *pv)
{
    SensorSample_t xSample;
    TickType_t xLast = xTaskGetTickCount();
    (void)pv;

    for (;;) {
        if (bsp_i2c_read_env(&xSample.sTemperature, &xSample.usHumidity) == 0) {
            xSample.ulTimestamp = xTaskGetTickCount();
            if (xQueueSend(xSampleQueue, &xSample, pdMS_TO_TICKS(5)) != pdPASS) {
                g_stats.sample_drops++;
            }
        } else {
            g_stats.sensor_errors++;
        }

        g_stats.sensor_heartbeat++;
        xTaskDelayUntil(&xLast, pdMS_TO_TICKS(10));
    }
}
/* process_task.c: filter then hand off */
static void vProcessTask(void *pv)
{
    SensorSample_t xIn;
    Record_t xOut;
    (void)pv;

    for (;;) {
        if (xQueueReceive(xSampleQueue, &xIn, portMAX_DELAY) != pdPASS) {
            continue;
        }

        xOut.ulTimestamp = xIn.ulTimestamp;
        xOut.sFiltered   = moving_average_update(&g_filter, xIn.sTemperature);
        xOut.ucFlags     = threshold_flags(xOut.sFiltered, g_threshold);

        if (xQueueSend(xRecordQueue, &xOut, pdMS_TO_TICKS(20)) != pdPASS) {
            g_stats.record_drops++;
        }
        g_stats.process_heartbeat++;
    }
}

Note the ownership: sensor is the only writer of the I2C device, process is the only writer of the filter state, storage is the only writer of the SD card. No mutex is needed anywhere in this data path.

The command line

/* ISR: push bytes into a stream buffer, no parsing here. */
void USART2_IRQHandler(void)
{
    BaseType_t xWoken = pdFALSE;
    uint8_t ucByte;

    if (uart_rx_ready()) {
        ucByte = uart_read_byte();
        xStreamBufferSendFromISR(xCliRx, &ucByte, 1, &xWoken);
    }
    portYIELD_FROM_ISR(xWoken);
}

/* Task: line assembly + dispatch */
static void vCliTask(void *pv)
{
    char cLine[96];
    size_t uxLen = 0;
    uint8_t ucByte;
    (void)pv;

    for (;;) {
        if (xStreamBufferReceive(xCliRx, &ucByte, 1, portMAX_DELAY) != 1) {
            continue;
        }

        if (ucByte == '\r' || ucByte == '\n') {
            if (uxLen > 0) {
                cLine[uxLen] = '\0';
                cli_dispatch(cLine);       /* may reply via a mutexed UART */
                uxLen = 0;
            }
        } else if (uxLen < sizeof cLine - 1) {
            cLine[uxLen++] = (char)ucByte;
        } else {
            uxLen = 0;                     /* overflow: drop the line */
        }
    }
}

Replies go through one function that takes a UART mutex or, better, through a TX queue drained by a single writer. Two tasks calling printf on the same UART without arbitration produce interleaved, useless output.

Health and watchdog

static void vHealthTask(void *pv)
{
    uint32_t ulLastSensor = 0, ulLastStorage = 0;
    (void)pv;

    for (;;) {
        vTaskDelay(pdMS_TO_TICKS(1000));

        if (g_stats.sensor_heartbeat == ulLastSensor) {
            fault_raise(FAULT_SENSOR_STALLED);
        }
        if (g_stats.storage_heartbeat == ulLastStorage) {
            fault_raise(FAULT_STORAGE_STALLED);
        }
        ulLastSensor  = g_stats.sensor_heartbeat;
        ulLastStorage = g_stats.storage_heartbeat;

        if (fault_is_active()) {
            led_set_pattern(PATTERN_FAST);
            if (fault_age_ms() > 2000) {
                fault_log_dump();
                nvic_system_reset();     /* last resort, after logging */
            }
        } else {
            led_set_pattern(PATTERN_SLOW);
            bsp_watchdog_feed();         /* only the healthy path feeds it */
        }
    }
}

The watchdog is fed only when every supervised task has reported in. A single stalled task therefore leads to a reset — which is the correct outcome — but only after the fault has been named and logged.

Bring-up milestones

  1. M1 — board alive. Clock, UART, LED, printf. No kernel yet.
  2. M2 — scheduler. Two tasks, different periods, xTaskDelayUntil, 1 kHz tick verified on a scope.
  3. M3 — data path. Sensor task at 100 Hz into a queue; a consumer prints rates and drops. No SD.
  4. M4 — storage. Batch 100 records, write to SD, survive a 200 ms simulated stall without losing data.
  5. M5 — CLI. status and rate work; replies never interleave with logs.
  6. M6 — health. Heartbeats, fault flags, fast/slow LED, stack watermarks in status.
  7. M7 — hardening. Watchdog, fault log across reset, 24-hour soak, power-cycle recovery.

Key takeaway

The capstone is deliberately boring: five tasks, one queue per data hand-off, one owner per resource, one supervisor. Boring is what makes it debuggable at 2 a.m.
