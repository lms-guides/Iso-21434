Queues: moving data safely

A queue is a fixed-length FIFO that copies items and blocks when full or empty. Those three properties remove an entire class of race conditions.

  • Producer / consumer
  • ISR hand-off
  • Backpressure
  • Queue sets

By the end of this module

  • Move fixed-size items between tasks and ISRs without shared globals.
  • Apply an explicit full-queue policy instead of hoping.
  • Size a queue from burst rate and worst-case consumer stall.

The API

QueueHandle_t xQueueCreate(UBaseType_t uxQueueLength, UBaseType_t uxItemSize);

BaseType_t xQueueSend(QueueHandle_t q, const void *item, TickType_t wait);
BaseType_t xQueueSendToFront(QueueHandle_t q, const void *item, TickType_t wait);
BaseType_t xQueueOverwrite(QueueHandle_t q, const void *item);   /* length must be 1 */
BaseType_t xQueueReceive(QueueHandle_t q, void *out, TickType_t wait);
BaseType_t xQueuePeek(QueueHandle_t q, void *out, TickType_t wait);

BaseType_t xQueueSendFromISR(QueueHandle_t q, const void *item,
                             BaseType_t *pxHigherPriorityTaskWoken);

UBaseType_t uxQueueMessagesWaiting(QueueHandle_t q);
BaseType_t xQueueReset(QueueHandle_t q);

xQueueSend blocks while the queue is full, and xQueueReceive blocks while it is empty. That blocking is the feature: producers apply backpressure instead of silently dropping, and consumers sleep instead of polling.

Copy semantics — and the trap

Because the queue copies uxItemSize bytes, small structs are safe and self-contained:

typedef struct {
    uint32_t ulTimestamp;
    int16_t  sTemperature;   /* 0.01 C  */
    uint16_t usHumidity;     /* 0.1 %RH */
} SensorSample_t;

QueueHandle_t xSensorQueue = xQueueCreate(16, sizeof(SensorSample_t));

If you send a pointer, the queue copies the pointer, not the payload. You then need a buffer pool and ownership rules, or you get the classic use-after-free where the producer overwrites a buffer the consumer is still reading.

Sending a struct copies it; sending a pointer copies only the address:

SensorSample_t s = read_sensor();
xQueueSend(xStructQueue, &s, portMAX_DELAY);  /* safe: struct is copied */

SensorSample_t *p = &s;
xQueueSend(xPointerQueue, &p, portMAX_DELAY);  /* unsafe: p dangles
                                                  after this iteration */

For large payloads: send a pointer to a buffer from a fixed pool, and return the buffer through a second queue. Never send a pointer to a stack local, and never assume the receiver is “fast enough”.

Producer/consumer with an ISR

static QueueHandle_t xUartRxQueue;

void USART2_IRQHandler(void)
{
    BaseType_t xWoken = pdFALSE;
    uint8_t ucByte;

    if (uart_rx_ready()) {
        ucByte = uart_read_byte();
        xQueueSendFromISR(xUartRxQueue, &ucByte, &xWoken);
    }
    portYIELD_FROM_ISR(xWoken);
}

static void vUartTask(void *pv)
{
    uint8_t ucByte;
    (void)pv;

    for (;;) {
        if (xQueueReceive(xUartRxQueue, &ucByte, portMAX_DELAY) == pdPASS) {
            cli_feed(ucByte);
        }
    }
}

portYIELD_FROM_ISR() is not decoration. Without it the woken task waits for the next tick, adding up to a full millisecond of latency to every byte.

Sizing, and what to do when it is full

Queue length is a latency budget, not a guess:

length >= worst_burst_rate * worst_consumer_stall

/* 100 Hz sensor, SD card that can stall 200 ms: */
100 * 0.2 = 20 items, plus ~25% margin  ->  24 slots

Then choose a policy and write it in a comment next to the send:

PolicyCodeUse for
BackpressurexQueueSend(q, &i, pdMS_TO_TICKS(5))Control data; slowing the producer is correct
Drop newestxQueueSend(q, &i, 0) and count failuresDisplay refreshes, telemetry
Drop oldestreceive one, then send“Latest value” streams
Overwritelength-1 queue + xQueueOverwriteSetpoints, latest command

Queue sets

A task can block on only one queue. If it must serve three sources that share state, a queue set lets it wait on all of them:

QueueSetHandle_t xSet = xQueueCreateSet(lenA + lenB + lenC);

xQueueAddToSet(xQueueA, xSet);
xQueueAddToSet(xQueueB, xSet);
xQueueAddToSet(xQueueC, xSet);

QueueHandle_t xActive = xQueueSelectFromSet(xSet, portMAX_DELAY);

if (xActive == xQueueA) {
    xQueueReceive(xQueueA, &msg, 0);   /* the item is guaranteed present */
}

Prefer separate tasks unless the sources share state that must be handled atomically. A queue set is a scalpel, not a default.

Key takeaway

The queue is where you decide what “full” means. Decide once, in code, and count the losses; otherwise the field will decide for you.
