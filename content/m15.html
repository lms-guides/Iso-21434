Your first project, step by step

One board, three tasks, a queue, a debounced button, a UART console and a stats command. Every file and every command, in the order you should do them.

  • NUCLEO-F411RE
  • CubeMX + CubeIDE
  • 3 tasks
  • Hands-on

By the end of this module

  • Create a FreeRTOS project from an empty CubeMX project and prove the scheduler runs.
  • Turn a button press into a debounced event, delivered by queue to another task.
  • Build a UART command console and a diagnostics command you will reuse in every project.

What you are building

A “button + LED console” — deliberately small, but it exercises every mechanism you will use in a real product:

  • An LED toggles at a configurable rate (default 500 ms).
  • Pressing the user button prints a timestamped line over serial, exactly once per press.
  • A UART console accepts help, rate <ms>, led on|off and stats.
  • stats reports uptime, button count, the kernel heap minimum and each task's stack headroom.

Before you start

  • NUCLEO-F411RE (or any Nucleo-64; adjust pins if yours differs) and a micro-USB cable that carries data.
  • STM32CubeMX and STM32CubeIDE installed, with the STM32CubeF4 package downloaded.
  • A serial terminal: PuTTY, screen, or python3 -m serial.tools.miniterm /dev/ttyACM0 115200.
  • 45 minutes for Steps 1–3, then the rest in a second sitting.

Step 1 — Prove the board works, bare metal

Never add an RTOS to a board you have not blinked. This isolates wiring and toolchain problems from kernel problems.

  1. New project in CubeMX → Board Selector → NUCLEO-F411RE → Start Project.
  2. Clock: leave the default HSI at 16 MHz for now. It is accurate enough for 115200 baud and removes the clock-tree step from your first session.
  3. SYS → Debug: Serial Wire. Keep the HAL timebase on SysTick for this bare-metal step; you will move it in Step 2.
  4. PA5: GPIO_Output, user label LED, default low.
  5. PC13: GPIO_EXTI13, pull-up, falling edge, user label BTN.
  6. USART2: Asynchronous, 115200 8N1. Pins PA2/PA3 are already assigned by the board.
  7. Project Manager: name rtos-lab, Toolchain CubeIDE (or Makefile/CMake), “generate peripheral initialization as a pair of .c/.h files”.
  8. Generate Code, open the project, and put this in while (1):
HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
HAL_Delay(500);

Build (Ctrl+B in CubeIDE), flash (Run), and confirm the LED blinks at 1 Hz. If it does not, stop here and fix that first — check the board's user manual for the correct LED pin if your board is not an F411RE.

Checkpoint 1

LED blinking, no errors, and you know which COM port the ST-Link enumerated. Do not continue until this is true.

Step 2 — Add the kernel and one task

Go back to CubeMX and enable the middleware:

  1. Middleware → FREERTOS → Interface: CMSIS_V2. This is only to get the kernel integrated and configured by the tool; all code you write next uses the native API.
  2. Config parameters, then set the values in the table below.
  3. NVIC: enable USART2 global interrupt and EXTI line[15:10] interrupts, both with preemption priority 6, subpriority 0.
  4. Generate Code. CubeMX will offer to move the HAL timebase to TIM6 — accept, because SysTick now belongs to FreeRTOS.

Start with just the heartbeat task and a print helper. Add this to app.c:

#include "app.h"
#include "main.h"
#include <stdio.h>
#include <stdarg.h>

static SemaphoreHandle_t xPrintMutex;

void app_print(const char *fmt, ...)
{
    char buf[128];
    va_list ap;
    int n;

    va_start(ap, fmt);
    n = vsnprintf(buf, sizeof buf, fmt, ap);
    va_end(ap);

    if (n <= 0) return;
    if (n >= (int)sizeof buf) n = sizeof buf - 1;

    if (xSemaphoreTake(xPrintMutex, pdMS_TO_TICKS(50)) == pdTRUE) {
        HAL_UART_Transmit(&huart2, (uint8_t *)buf, (uint16_t)n, 100);
        xSemaphoreGive(xPrintMutex);
    }
}

static void vHeartbeatTask(void *pv)
{
    TickType_t xLast = xTaskGetTickCount();
    (void)pv;

    for (;;) {
        HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        xTaskDelayUntil(&xLast, pdMS_TO_TICKS(500));
    }
}

void app_init(void)
{
    xPrintMutex = xSemaphoreCreateMutex();
    configASSERT(xPrintMutex != NULL);

    xTaskCreate(vHeartbeatTask, "hb", 256, NULL, 2, NULL);
}

Build, flash, and confirm the LED blinks at exactly 500 ms. If it blinks once and stops, the scheduler did not start or the heap was too small — see the troubleshooting table at the end.

Step 3 — Button press → debounce timer → queue → event task

A mechanical button bounces for a few milliseconds. Do not debounce in the ISR with a delay; start a one-shot timer, and let the timer callback decide whether the button is still down.

typedef struct {
    uint32_t ulTick;
} event_t;

static QueueHandle_t xEventQueue;
static TimerHandle_t xDebounceTimer;
static TaskHandle_t  xEventHandle;

static volatile uint32_t ulButtonCount;
static volatile uint32_t ulEventDrops;

/* 50 ms one-shot, runs in the timer daemon task */
static void vDebounceCallback(TimerHandle_t xTimer)
{
    event_t ev;

    (void)xTimer;

    if (HAL_GPIO_ReadPin(BTN_GPIO_Port, BTN_Pin) == GPIO_PIN_RESET) {
        ev.ulTick = xTaskGetTickCount();
        if (xQueueSend(xEventQueue, &ev, 0) != pdPASS) {
            ulEventDrops++;
        }
    }
}

/* EXTI ISR: restart the timer, do nothing else */
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    BaseType_t xWoken = pdFALSE;

    if (GPIO_Pin == BTN_Pin) {
        xTimerStartFromISR(xDebounceTimer, &xWoken);
    }
    portYIELD_FROM_ISR(xWoken);
}

static void vEventTask(void *pv)
{
    event_t ev;
    (void)pv;

    for (;;) {
        if (xQueueReceive(xEventQueue, &ev, portMAX_DELAY) == pdPASS) {
            ulButtonCount++;
            app_print("[%lu ms] button pressed (#%lu)\r\n",
                      (unsigned long)ev.ulTick,
                      (unsigned long)ulButtonCount);
        }
    }
}

Extend app_init():

xEventQueue   = xQueueCreate(16, sizeof(event_t));
xDebounceTimer = xTimerCreate("deb", pdMS_TO_TICKS(50), pdFALSE, NULL,
                              vDebounceCallback);

configASSERT(xEventQueue != NULL);
configASSERT(xDebounceTimer != NULL);

xTaskCreate(vEventTask, "evt", 384, NULL, 3, &xEventHandle);

Why this shape works:

  • The ISR is three lines and touches no hardware state beyond starting a timer.
  • The timer callback runs in a task, so it may read a pin and post to a queue — an ISR should not.
  • Every bounce restarts the 50 ms window, so only the final, stable edge produces an event.
  • Exactly one task owns the counter, so no lock is needed on ulButtonCount.
Checkpoint 3

One line per press, none for a light tap-and-hold. If you get two or three lines, raise the debounce to 80 ms and check whether your board has a hardware debounce capacitor.

Step 4 — UART console: interrupt → stream buffer → CLI task

Bytes arrive unpredictably and lines need parsing, so the ISR should only move bytes and the task should do the thinking.

static StreamBufferHandle_t xCliRx;
static TaskHandle_t xCliHandle;
static uint8_t ucRxByte;

/* Called from the UART ISR context */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    BaseType_t xWoken = pdFALSE;
    uint8_t b;

    if (huart->Instance != USART2) return;

    b = ucRxByte;
    HAL_UART_Receive_IT(&huart2, &ucRxByte, 1);   /* re-arm first */
    xStreamBufferSendFromISR(xCliRx, &b, 1, &xWoken);
    portYIELD_FROM_ISR(xWoken);
}
static void vCliTask(void *pv)
{
    char line[64];
    size_t len = 0;
    uint8_t ch;
    bool lastCR = false;

    (void)pv;
    app_print("\r\nRTOS lab ready. Type 'help'.\r\n> ");

    for (;;) {
        if (xStreamBufferReceive(xCliRx, &ch, 1, portMAX_DELAY) != 1) {
            continue;
        }

        if (ch == '\r' || ch == '\n') {
            if (ch == '\n' && lastCR) { lastCR = false; continue; }
            lastCR = (ch == '\r');

            if (len > 0) {
                line[len] = '\0';
                app_print("\r\n");
                cli_exec(line);
                len = 0;
                app_print("> ");
            }
            continue;
        }
        lastCR = false;

        if (ch == 0x7F || ch == '\b') {
            if (len > 0) { len--; app_print("\b \b"); }
        } else if (len < sizeof line - 1) {
            line[len++] = (char)ch;
            app_print("%c", ch);          /* local echo */
        }
    }
}

Add to app_init(), after creating the stream buffer, and remember to arm the first receive:

xCliRx = xStreamBufferCreate(128, 1);
configASSERT(xCliRx != NULL);
xTaskCreate(vCliTask, "cli", 512, NULL, 1, &xCliHandle);

HAL_UART_Receive_IT(&huart2, &ucRxByte, 1);
Why a mutex around printing?

Three tasks write to one UART. A mutex keeps whole lines from interleaving. It also means a print holds the lock for the duration of the transfer — at 115200, a 100-character line is about 9 ms. That is acceptable here; Module 14's checklist asks you to move TX to its own task for a product.

Step 5 — Commands: change the blink rate at runtime

Commands travel as values through a queue, so the heartbeat task owns its own period and nobody mutates it from another context.

typedef enum {
    CMD_RATE = 1,
    CMD_LED
} cmd_id_t;

typedef struct {
    cmd_id_t id;
    uint32_t arg;
} command_t;

static QueueHandle_t xCmdQueue;

/* Owned by the heartbeat task only */
static TickType_t xBlinkPeriod = pdMS_TO_TICKS(500);
static bool bBlinkEnabled = true;

static void handle_command(const command_t *cmd)
{
    if (cmd->id == CMD_RATE) {
        xBlinkPeriod = pdMS_TO_TICKS(cmd->arg);
        app_print("rate set to %lu ms\r\n", (unsigned long)cmd->arg);
    } else if (cmd->id == CMD_LED) {
        bBlinkEnabled = (cmd->arg != 0);
        if (!bBlinkEnabled) {
            HAL_GPIO_WritePin(LED_GPIO_Port, LED_Pin, GPIO_PIN_RESET);
        }
        app_print("led %s\r\n", bBlinkEnabled ? "on" : "off");
    }
}

static void vHeartbeatTask(void *pv)
{
    command_t cmd;
    TickType_t xLast = xTaskGetTickCount();
    (void)pv;

    for (;;) {
        while (xQueueReceive(xCmdQueue, &cmd, 0) == pdPASS) {
            handle_command(&cmd);
        }

        if (bBlinkEnabled) {
            HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin);
        }

        xTaskDelayUntil(&xLast, xBlinkPeriod);
    }
}
static void cli_exec(char *line)
{
    if (strcmp(line, "help") == 0) {
        app_print("commands: help | rate <ms> | led on|off | stats\r\n");
    } else if (strncmp(line, "rate ", 5) == 0) {
        char *end = NULL;
        unsigned long v = strtoul(line + 5, &end, 10);

        if (end == line + 5 || *end != '\0' || v < 50 || v > 5000) {
            app_print("usage: rate <50..5000>\r\n");
            return;
        }
        command_t cmd = { CMD_RATE, (uint32_t)v };
        if (xQueueSend(xCmdQueue, &cmd, pdMS_TO_TICKS(10)) != pdPASS) {
            app_print("command queue full\r\n");
        }
    } else if (strcmp(line, "led on") == 0 || strcmp(line, "led off") == 0) {
        command_t cmd = { CMD_LED, (uint32_t)(line[4] == 'o' && line[5] == 'n') };
        (void)xQueueSend(xCmdQueue, &cmd, pdMS_TO_TICKS(10));
    } else if (strcmp(line, "stats") == 0) {
        print_stats();
    } else if (line[0] != '\0') {
        app_print("unknown command: %s\r\n", line);
    }
}

Create the queue in app_init() before the heartbeat task, and add the headers <string.h> and <stdlib.h> to app.c.

Checkpoint 5

rate 200 changes the blink within one old period; rate 10 is rejected with the usage line; led off stops toggling and leaves the LED dark. Note that the command is acknowledged by the heartbeat task, not the CLI task — that is the ownership paying off.

Step 6 — A stats command you will keep forever

static TaskHandle_t xHeartbeatHandle;

static void print_stats(void)
{
    app_print("uptime   : %lu s\r\n",
              (unsigned long)(xTaskGetTickCount() / configTICK_RATE_HZ));
    app_print("buttons  : %lu\r\n", (unsigned long)ulButtonCount);
    app_print("drops    : %lu\r\n", (unsigned long)ulEventDrops);
    app_print("heap min : %u bytes\r\n",
              (unsigned)xPortGetMinimumEverFreeHeapSize());
    app_print("stack hb : %u words free\r\n",
              (unsigned)uxTaskGetStackHighWaterMark(xHeartbeatHandle));
    app_print("stack evt: %u words free\r\n",
              (unsigned)uxTaskGetStackHighWaterMark(xEventHandle));
    app_print("stack cli: %u words free\r\n",
              (unsigned)uxTaskGetStackHighWaterMark(xCliHandle));
}

Pass &xHeartbeatHandle as the last argument of xTaskCreate for the heartbeat task. Then leave the board running for ten minutes, press the button a few dozen times, and run stats again. Any number that moved towards zero is a bug you just found before a customer did.

Step 10 — Make it yours

Pick one and only one. Each is a 30–60 minute extension that adds a new mechanism rather than more of the same:

  1. Second button, counting semaphore. Add a “mode” button; the ISR gives a counting semaphore, and a task consumes one mode change per press.
  2. Replace the polled command queue. Have the CLI task notify the heartbeat task instead of the heartbeat polling with a zero timeout. Compare CPU time in stats.
  3. ADC task. Sample one channel at 1 kHz with DMA, send samples through a queue, and print a 10-sample average once per second.
  4. Tickless idle. Enable configUSE_TICKLESS_IDLE, measure current in run and idle, and explain the difference.
  5. Health task and watchdog. Add the heartbeat counters and IWDG refresh from Module 13, then block the CLI task on purpose and watch the reset.
  6. Console TX task. Move all UART output into one task fed by a queue, removing the 9 ms mutex hold from every caller.

What you just proved

  • Module 4: tasks with different priorities, and a periodic task that does not drift.
  • Module 6: a queue that carries events between an ISR-driven producer and a consumer.
  • Module 7: a mutex protecting a shared peripheral, with a timeout.
  • Module 8: a stream buffer for bytes and a queue for commands.
  • Module 9: an ISR that starts a timer and returns in microseconds.
  • Module 10: measured stack and heap margins instead of guesses.
Key takeaway

The project is small on purpose: ownership is obvious, every wait is bounded, and the diagnostics are built in from day one. Scale that shape up, not the number of tasks.
